# 发布与交付验收

把已实现的范围交付到约定环境，并提供能核对的结果。适配项目已有发布方式，不预设云厂商、Docker 或 CI 平台。

## 明确本次动作

读取目标仓库 `AGENTS.md`、启动与部署说明、CI 配置、相关任务和最近验证记录，检查工作区。确定交付版本或构建产物、目标环境/账号、包含的变更及发布方式；本地未提交变更需要说明如何进入产物，避免部署错版本。

- **只要求准备/审查**：完成配置、命令、验证与恢复方案，交付可审阅结果后停止。
- **已明确要求部署到某环境**：沿用已有授权，准备就绪后继续发布并做目标环境验证，不因切换阶段再次确认。
- **目标环境不明或出现授权之外的代价**：先完成可独立准备的工作，列出具体目标/差异后只确认缺失部分。创建付费资源、域名/DNS 调整、破坏性迁移或生产数据写入等不能从一般开发请求中推定授权。

`assets/` 相对于本 skill；`docs/` 等输出路径相对于目标仓库。沿用已有运维文档和发布记录，避免另建重复目录。

## 发布准备

按实际运行形态检查，不为静态页面或无数据库项目补不存在的服务：

| 检查面 | 需要核实的内容 |
| --- | --- |
| 版本与验证 | 本次范围、代码/产物标识；相关测试、类型/lint 和构建结果，沿用匹配同一版本的可靠证据 |
| 运行与配置 | 运行时、启动命令、端口、健康检查、服务依赖；环境变量名称及来源，客户端公开配置与服务端密钥隔离 |
| 前后端连接 | API 地址、代理、CORS、Cookie/回调域名与 HTTPS；核实构建时和运行时变量的区别，防止页面仍调用本地或旧接口 |
| 数据与权限 | 目标数据库、迁移状态、授权策略；测试账号/数据仅在适用环境使用，不将开发种子写入生产 |
| 恢复与观测 | 可用的上一版本、恢复操作、失败判据；关键日志/指标入口及健康检查，敏感信息脱敏 |

涉及 schema 或已有数据时，说明应用与数据库的兼容窗口、迁移/回填顺序和恢复方式；在隔离的验证库或已授权用于迁移测试的环境验证。只要求发布准备时，不在正式目标环境执行迁移或切换；无法隔离验证则记录缺口。破坏性步骤执行前核实实际授权与备份/恢复可行性。应用回退不等于数据库可逆；不能无损回退时明确向前修复或备份恢复方案。

先修复可解决的准备问题。关键验证失败或迁移/恢复条件不满足时记录阻塞，不继续把同一风险发布到目标环境。

## 执行与发布后验证

1. 使用已有发布脚本、CI 或平台工具部署已核实的产物；记录目标、版本、实际命令/任务 ID 和结果，不在记录中输出密钥。
2. 依既定顺序执行必要迁移和应用切换，检查发布任务状态。失败时保留诊断证据，按已授权恢复方案处理；没有新证据时不盲目重复部署。
3. 在**目标环境**验证健康检查与本次关键用户/API 路径。全栈项目核实页面 → API → 数据读取/保存的链路，以及适用的认证、拒绝访问和失败反馈；使用允许的测试数据，记录并清理临时数据。生产写入测试需要相应授权，可用只读路径或已有合成检查替代并标明覆盖范围。
4. 查看必要日志和错误信号，确认前后端版本与配置匹配。健康接口成功或平台显示 deployed 只能证明部分状态，不能代替业务冒烟。
5. 冒烟失败时判定影响范围，执行授权内的恢复或修复并重新验证；不可逆或需要额外授权的动作先提交具体方案。分别记录功能状态、部署状态和业务验收状态。

目标环境无法访问、凭据不足或关键路径无法验证时，保留“待验证/受阻”状态并给出下一步。用户已授权的独立准备工作继续完成。

## 交付记录

读取 [发布记录模板](assets/release-record-template.md)，复用项目已有发布日志或保存到 `docs/发布记录/<版本或日期-环境>.md`；同名记录追加本次尝试，不覆盖历史。轻量静态部署可以在既有任务或回复中记录等价证据。

最终提供目标环境链接（适用时）、版本、验证结果、已知缺口及恢复信息。只有部署和必要目标环境验证均通过时才报告该环境发布成功；准备完成、部署待验证、已恢复等状态分别写明。
