# 阶段边界与任务衔接

Skill 定义默认职责与产出，帮助控制范围。用户当前请求和已确认的授权决定本次任务执行到哪一步。

## 如何推进

| 用户请求 | 执行方式 |
| --- | --- |
| 只做需求、设计或规划 | 完成指定产出后停止，不附带实现或外部操作 |
| 明确要求修改或端到端完成 | 补齐必要分析后继续执行；可使用下一阶段 skill，缺少该 skill 时按等价步骤处理 |
| 需求、设计已有明确确认 | 沿用已确认结论，不因切换阶段重复询问 |
| 存在影响范围、行为或兼容性的关键歧义 | 先提供具体选项和建议，只确认会影响结果的决策 |
| 涉及删除、覆盖、部署或远端操作 | 判断是否在已有授权范围内；超出范围时先提供可审阅结果，再申请所需授权 |

## 按规模选择产出

- **轻量修改**：需求明确、局部且低风险，在回复或已有任务记录中说明目标、改动和验证即可。
- **普通功能**：保留可追溯的需求、设计和任务；已有文档可直接复用或合并记录。
- **重大变更**：涉及跨模块、数据迁移、权限、外部契约或重要架构取舍时，明确影响、验收、风险及回滚方案。

发现隐藏复杂度时重新评估任务规模，说明新增问题；只有需要用户作出新决策时才暂停。

## 汇报边界

- 完成状态必须来自实现与验证证据，文件存在或单个测试通过不能代替功能验收。
- 工具不可用时选择可行替代方案；没有等价验证手段时标记未验证并说明缺口。
- 保留用户已有改动。修改授权不自动包含提交、推送、发布或发送消息的授权。
