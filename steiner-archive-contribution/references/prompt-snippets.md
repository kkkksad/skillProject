# 提示词片段

## 位置与目标

从 `templates/prompt.md` 开始，将片段保存到 `content/prompts/snippets/<slug>.md`。一个片段解决一个明确问题。

- 标题使用“动作 + 目标”命名。
- `description` 说明“输入什么、得到什么”。
- 正文解释适用场景、使用步骤、环境约束和预期输出。
- 需要图片或 GIF 时放到片段目录使用的 `assets/` 位置，并通过相对路径引用；素材应脱敏、简短，并提供等价的文字步骤。纯文本任务不必强行配图。

## 可复制提示词

将可直接交给 AI 的完整文本放在 frontmatter 的 `prompt.text` 中。使用 YAML 的 `|-` 保留换行并去掉末尾空行：

```yaml
prompt:
  text: |-
    这里放完整提示词。
    不要混入投稿说明、图注或要求用户删除的注释。
```

复制区域之外的正文用于解释功能和展示效果。

## 填空项

占位符统一使用 `{{key}}`。`key` 必须以小写英文字母开头，只包含小写英文、数字和下划线，例如 `project_name`。

每个占位符都必须在 `prompt.inputs` 中声明：

| 字段 | 要求 |
| --- | --- |
| `key` | 与正文占位符完全一致 |
| `label` | 用户能理解的字段名称 |
| `description` | 填什么、格式、范围或如何获取；不得缺失 |
| `example` | 一份可参考的输入，不会自动填入 |

- 声明项与占位符必须一一对应，不得重复或遗漏。
- 所有声明的填空项都应完成填写后才能复制完整提示词。
- 允许留空时，明确要求用户填写“无”或“不适用”。
- 不要用省略号、方括号或未声明的变量暗示还要填空。
- 无需任何输入时使用 `inputs: []`。

## 验证与维护

`pnpm check` 只能检查占位符、输入定义、重复项和必填说明等结构规则，不能证明提示词有效。完成实际场景测试和人工审查前保持 `status: draft`。

核验记录应包含：

- 实际使用的模型或工具版本。
- 输入示例和输出摘要。
- 人工检查结论。
- 已知限制和未覆盖场景。

完成场景验证与审查后再改为 `reviewed`，并同步维护人、适用范围和 `lastVerified`。弃用时改为 `deprecated`，说明原因和替代片段。
