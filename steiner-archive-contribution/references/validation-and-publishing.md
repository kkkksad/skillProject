# 验证与发布

## 环境

- Node 版本以仓库 `.node-version` 为准。
- pnpm 版本以 `package.json` 的 `packageManager` 为准。
- 首次使用运行 `pnpm install`；需要可视编辑时运行 `pnpm dev` 并打开终端输出的 Local 地址。
- 以 `package.json` 中实际存在的 scripts 为准，不要假设旧命令仍然有效。

## 提交前检查

知识文章和提示词片段通常执行：

```sh
pnpm check
pnpm build
pnpm check:links
```

按改动类型补充检查：

- 提示词片段：打开本地详情页，检查预览、换行、原始复制、填写后复制、清空恢复和效果说明。
- 搜索或生产行为：运行 `pnpm preview` 后检查。开发服务器不生成最终 Pagefind 搜索索引。
- Agent Skill：执行仓库当前的 Skills 同步命令，检查源文件、引用资源和生成页面是否一致。
- 部署子路径：按仓库说明设置完整的 `SITE_URL`，重新构建并同时检查根路径和部署子路径。

命令失败时先修复根因再重跑。构建成功不能替代内容验证、模型效果验证或维护人审查。

## Git 与 MR

没有用户明确授权时，只修改和验证工作区文件，不执行提交或远端操作。获得授权后：

1. 检查 `git diff` 和目标文件，排除无关改动。
2. 只暂存本次贡献需要的文件。
3. 使用说明实际改动的提交信息。
4. 创建 MR，由相关领域或资产维护人审查。
5. 合入默认分支后由 CI 生成静态站点产物。

不要把生成产物、预览截图、临时抓取文件或无关工作区改动混入 MR。
